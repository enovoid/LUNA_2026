# @luna/web — 루나 사이트

Astro 정적 사이트. 빌드할 때만 Postgres를 읽고, 방문자 요청은 DB·Notion에 닿지 않는다.

## 로컬 실행

```bash
pnpm install
pnpm dev                 # DATABASE_URL이 없으면 목업 데이터로 뜬다
pnpm --filter @luna/web build && pnpm --filter @luna/web preview
```

| 환경 변수          | 설명                                                                                                                              |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `LUNA_DATA_SOURCE` | `db` 또는 `mock`. 비우면 `DATABASE_URL`이 있을 때 db, 없을 때 mock. CI에서 둘 다 없으면 빌드를 멈춘다(목업이 배포되는 사고 방지). |
| `DATABASE_URL`     | 빌드 시 읽을 Postgres                                                                                                             |
| `R2_PUBLIC_URL`    | 사진 주소의 앞부분. 없으면 사진 대신 자리표시를 그린다                                                                            |
| `SITE_URL`         | canonical·sitemap·OG의 절대 주소. TODO: 도메인 확정                                                                               |

목업으로 빌드한 화면은 푸터에 빨간 글씨로 "목업 데이터로 빌드한 화면"이 붙는다.

## 구조

```
src/
  content/site.ts        Notion에 없는 고정 값: 창립 연도, 인트로 좌표·배율
                         (모집 정보·연락처는 관리자 페이지 → DB site_settings → loadSiteData().settings)
  lib/data/              데이터 진입점(db.ts / mock.ts), 행 검증
  lib/content.ts         정렬·묶음·통계·이름 연결
  lib/image.ts           R2 srcset(480/960/1600)
  components/            Header, TabBar, Footer, ScrollIntro, 카드, Picture, EmptyState, Filter, NavPerf
  scripts/               intro.ts(GSAP), reveal.ts, header-bar.ts, segmented.ts(필터), nav-pending.ts(이동 스켈레톤)
  styles/                tokens.json(디자인 시스템 원본) → tokens.css(생성), global.css(Tailwind v4 @theme)
public/intro/            인트로 사진 4장 + 달 고해상도 2장
public/sw.js             서비스 워커(재방문 캐시)
public/_headers          Cloudflare 캐시 헤더
```

- 디자인 토큰: `tokens.json`을 고친 뒤 `pnpm --filter @luna/web tokens`로 `tokens.css`를 다시 만든다.
- 이미지 규칙(동기화 작업과 약속): DB `image_key` = `members/<sha256>` 같은 접두어, 파일은 `<key>-480|960|1600.webp`, 너비·높이는 1600 이하로 줄인 최대본 크기.

## 스크롤 인트로

`ScrollIntro.astro` + `scripts/intro.ts`. 높이 `100svh × (travel + 1)`(데스크톱 travel 3.35, 모바일 2.9) 구역 안의 sticky 무대에서 진행률 p 하나로 계산한다. 달→로고 전환은 PR #7에서 맞춘 타임라인을 그대로 되살렸고(사용자 결정, 2026-10-30), 그 뒤에 구름 구간을 붙였다. 흰 화면은 없다. 구름이 로고를 덮는 p=1에서 고정이 풀리고 무대가 그대로 위로 올라간다(사용자 요청: "로고가 어느 정도 가려지면 그냥 스크롤이 내려가게").

| p           | 일                                                                                        |
| ----------- | ----------------------------------------------------------------------------------------- |
| 0–0.045     | "스크롤해서 달에게 다가가기" 사라짐                                                       |
| 0.045–0.364 | 하늘이 달 중심으로 지수 확대(데스크톱 2.4배, 모바일 1.7배). 0.045–0.33 동안 달이 가운데로 |
| 0.17–0.318  | 도시가 1.6배 빠르게 커지며 사라짐(시차)                                                   |
| 0.205–0.386 | 달 둘레 빛과, 달 크기 구멍이 뚫린 어두운 고리가 바깥부터 덮음                             |
| 0.364–0.455 | 사진 전체가 어두워짐(가운데 `--surface-1` → 가장자리 `--bg`)                              |
| 0.386–0.477 | 달이 있던 자리에서 같은 크기의 로고가 떠오름                                              |
| 0.477–0.568 | 로고가 제 크기로 줄며 세로 자리로                                                         |
| 0.568–0.659 | 로고가 옆으로 비켜 서며 "LUNA"가 나옴(HIG 스프링, bounce 0.25)                            |
| 0.648–0.727 | 머리글 + "세상을 비추는 달, LUNA"(h1)                                                     |
| 0.727–0.818 | 로고와 제목이 완전히 보이는 구간                                                          |
| 0.818–1     | 구름이 닫히며 로고를 **덮음**(위 구름은 내려오며 가로 8%, 아래 구름은 올라오며 반대로 6%) |
| 0.864–1     | 무대 아래 22%가 바탕색으로 어두워짐(다음 구역과 이음새 없이)                              |
| 0.909–1     | 상단 로고 등장                                                                            |
| 1 이후      | 고정이 풀려 구름 덮인 무대가 그대로 위로 올라가고 소개 구역이 이어짐                      |

- 움직임은 transform·opacity만. 레이아웃 값(로고 위치)은 크기가 바뀔 때만 잰다. 어두운 배경이 다 덮은 뒤에는 사진 레이어를 `visibility: hidden`으로 빼 합성 비용을 줄인다.
- `scrub: true`, pin 대신 sticky. 스크롤 잠금·자동 스냅은 없다.
- 구름은 로고를 덮는다. 다크 최종안은 "구름이 로고 뒤에서 닫힘"이었지만 사용자 요청(2026-10-30, "구름 뒤로 로고가 숨었으면")으로 순서를 바꿨다. 정적 화면에서만 로고·제목이 구름 위에 있다.
- `prefers-reduced-motion`, JS 꺼짐, GSAP 로드 실패 → 100svh 한 화면에 p=0.85 상태(로고 + 제목, 구름이 반쯤 걸친 장식). 움직임 줄이기면 GSAP을 아예 받지 않는다.
- 다크 최종안의 타임라인(520svh, 9배 확대 후 달빛 흰 막)은 사용자 결정으로 쓰지 않는다. 확대된 사진의 해상도 한계는 흰 막 대신 어두운 고리와 어두운 막이 가린다.
- 다크 최종안은 인트로를 Astro 아일랜드(`client:load`)로 적었지만, 프레임워크 런타임 없이 같은 시점에 실행되는 Astro `<script>`(모듈)로 둔다. 홈 JS를 그만큼 아낀다.
- 이음새: 인트로 마지막 화면과 소개 구역 맨 윗줄이 모두 `var(--bg)`이고, 소개 구역은 `margin-top: -1px`로 겹친다. 배율 100·110·125%, 390px(3배 밀도)에서 경계 ±4px 줄의 색이 #1C1C1E와 최대 2단계(0~255 기준) 차이로, 눈에 보이는 줄이 없다.
- 사진: Unsplash(`public/intro/README.md`). `site.ts`의 `introScene.usePhotos`를 끄면 같은 좌표의 CSS 임시 하늘·달을 그린다.
- 구도: 원본 하늘 사진은 달이 위쪽(데스크톱 22.6%)에 붙어 있어, 달과 달무리만 3분할선(데스크톱 33.3%, 모바일 36%)으로 옮긴 하늘 사진을 쓴다(사용자 요청). 다크 최종안 좌표는 원본 기준이라 `introScene` 좌표만 옮긴 사진에 맞췄다.
- 달 고해상도: 달 부분(400×400)만 Real-ESRGAN x4plus(BSD-3)로 4배 키운 1200px WebP를 하늘 레이어의 달 위에 겹친다. 확대해도 선명하다.

### 스크롤 길이

달→로고 구간은 PR #7에서 맞춘 길이(화면 2.8장) 그대로이고, 구름이 로고를 덮을 때까지만 더했다. 스크롤 거리는 데스크톱 335svh, 모바일 290svh다.

| 입력          | 기준으로 삼은 값                                                   | 인트로가 차지하는 양                    |
| ------------- | ------------------------------------------------------------------ | --------------------------------------- |
| 마우스 휠     | 한 칸 ≈ 100px(Chrome·Edge·Safari 기본), 이어서 굴릴 때 초당 6~10칸 | 3.35 × 900px ≈ 3,015px ≈ 30칸, 약 4~6초 |
| 트랙패드      | 한 번 쓸기 ≈ 400~1,500px(관성 포함)                                | 3~6번 쓸기                              |
| 휴대폰 손가락 | 끌기는 손가락 이동과 1:1(한 번 ≈ 화면 0.6장), 튕기기는 화면 1~3장  | 2.9 × 844px ≈ 2,450px, 튕기기 2~3번     |

## 모션(Apple HIG)

원칙과 근거는 [docs/design-references.md](../../docs/design-references.md)에 있다. 코드 위치만 적는다.

- 토큰: `global.css`의 `--spring-smooth|snappy|bouncy`(+`-dur`), `--press-dur`, `--press-scale`, `--fade-dur`. JS는 `lib/motion.ts`의 `springEase()`.
- 등장: `[data-reveal]`(묶음), `[data-reveal-item]`(묶음 안 순서대로 70ms씩) → `scripts/reveal.ts`
- 누름: `.btn`, `.pressable`, 탭 바 → 누르는 동안 0.97배, 떼면 snappy 스프링
- 필터: 선택 표시가 미끄러짐(`scripts/segmented.ts`), 카드는 View Transition으로 새 자리로 이동(`lib/filter-dom.ts`)
- 페이지 이동: `@view-transition { navigation: auto }` 크로스페이드, 헤더 내용·탭 바는 제자리. `view-transition-name`은 흐림이 걸린 요소 자신(탭 바 `ul`)이나 그 안쪽(헤더 `.site-header-inner`)에 둔다. 흐림 요소의 조상에 두면 그 조상이 backdrop root가 되어 Chromium에서 흐림이 사라진다.
- 동작 줄이기: 이동·확대는 모두 빼고 크로스페이드만 남긴다. 인트로는 정적 최종 화면.

## 렌더링·성능

- 이미지·카드는 모두 `aspect-ratio` 상자에 들어가 사진이 늦어도 CLS가 생기지 않는다. 사진엔 `width`·`height`·`loading="lazy"`·`decoding="async"`.
- 필터는 URL 쿼리가 있으면 첫 페인트 전 인라인 스크립트가 먼저 카드를 숨긴다(섬이 깨어날 때 흔들림 없음).
- 등장 효과·헤더 전환·탭 바·인트로는 transform·opacity만 바꾼다. 헤더 유리 배경은 별도 층의 opacity로 전환한다.
- JS(gzip): 홈 약 50KB(GSAP 코어 27 + ScrollTrigger 17 + 인트로 3 + 기타 2). 다른 페이지는 약 3KB(필터·이동 스켈레톤·등장 효과, 모두 인라인). 예산: 홈 70KB, 나머지 50KB.
- 필터는 React 섬 대신 정적 마크업 + 작은 스크립트(`segmented.ts`)다. React(약 65KB)를 받지 않는다.

### 페이지 이동·재방문 캐시

| 장치                                     | 하는 일                                                                                                                                                                                  |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Speculation Rules (`NavPerf.astro`)      | 링크에 마우스를 올리거나(약 200ms) 누르기 시작하면 다음 페이지를 미리 그려 둔다. 주 메뉴 페이지 HTML은 쉬는 시간에 미리 받는다. 지원하지 않는 브라우저는 무시(JS 0바이트)                |
| 이동 스켈레톤 (`scripts/nav-pending.ts`) | 누르고 120ms 안에 새 페이지가 안 오면 탭 선택을 먼저 옮기고 도착할 페이지 모양(격자·비율 같음)의 스켈레톤을 덮는다. 새 페이지가 오면 View Transition 크로스페이드로 바뀐다               |
| 사진 스켈레톤 (`Picture.astro`)          | 사진이 오는 동안 같은 상자에 빛이 지나간다. 동작 줄이기면 멈춘 회색 상자                                                                                                                 |
| 서비스 워커 (`public/sw.js`)             | 처음 방문 때 주 메뉴 5개 페이지와 그 JS·CSS를 Cache Storage에 받아 둔다. 다음부터 페이지는 캐시를 먼저 보여 주고 뒤에서 새 HTML로 바꿔 둔다. `/admin`·다른 출처(R2 사진)는 건드리지 않음 |
| HTTP 캐시 (`public/_headers`)            | `/_astro/*`(해시 파일) 1년 immutable, 인트로 사진 1주 + SWR, `sw.js` no-cache. HTML은 Cloudflare 기본(매번 ETag 확인)                                                                    |

- 쿠키를 쓰지 않는 이유: 쿠키는 요청마다 서버로 실려 가고 한 개 4KB 남짓이라 페이지·자산을 담을 수 없다. 자산은 HTTP 캐시와 Cache Storage가 맡는다.
- 배포 직후 첫 방문에는 예전 HTML이 한 번 보일 수 있다(뒤에서 갱신되어 다음 이동부터 새 내용). 캐시한 HTML이 쓰는 JS·CSS는 같이 받아 두므로 예전 HTML도 깨지지 않는다.
- 캐시 형식을 바꿀 때만 `sw.js`의 `VERSION`을 올린다.
- Pretendard는 유니코드 범위별 서브셋 woff2를 셀프 호스팅한다. 화면에 쓰인 글자 범위만 받고, Apple 기기는 시스템 서체가 먼저 잡혀 받지 않는다.

## Biome

루트 `biome check .`가 이 패키지도 검사한다. `apps/web/biome.json`은 Tailwind v4 문법(`@theme`)을 읽도록 CSS 파서 옵션만 켠다.
`.astro` 파일은 Biome이 프런트매터(맨 위 `---` 사이 TS)만 검사·정리하고, 아래 HTML 템플릿과 `<style>`은 건드리지 않는다(Biome 2.6의 Astro 지원 범위). 템플릿 오류는 `astro check`(typecheck)가 잡는다.

## 디자인 초안에서 바꾼 점(UX)

0. **전체 톤(Apple 다크 모드 기준)**: 사이트 전체가 다크 하나다(`<html data-theme="dark" class="theme-dark">`). 보라를 줄인 중립 회색으로, 바탕 `--bg` #1C1C1E → 카드 `--surface-1` #2C2C2E → 올라온 면 `--surface-2` #3A3A3C의 밝기 계층으로 구분한다(근거: `docs/design-references.md` "5. 다크 모드 색"). 사용자 결정에 따라 **테두리·그림자는 어디에도 쓰지 않는다**. 섹션 사이는 줄 대신 여백으로 나눈다. 라벤더는 누를 수 있는 것(버튼, 링크, 현재 탭)에만 쓴다. 글자색은 `html`에서 `--text`로 한 번만 정하고 상속한다. 아래 "색 대비" 참고.
1. **인트로 타임라인**: PR #7에서 맞춘 달→로고 전환을 되살리고(사용자 결정) 뒤에 구름 구간을 붙였다(위 "스크롤 인트로"). 구름은 로고를 덮는다.
2. **헤더 막대**: 인트로·소개 위에서는 막대 없이 투명하고, 그 아래로 내려가면 `rgb(28 28 30 / 0.7)`(바탕 #1C1C1E의 70%) + 20px 흐림 막대가 깔린다(경계선 없음, 사용자 결정).
3. **칩**: 연도·분류 칩은 `--surface-2` 바탕 + `--text`의 중립색이다. 정보 표시일 뿐 누르는 것이 아니라서 강조색을 쓰지 않는다. 1위 배지만 라벤더 바탕 + 어두운 글자.
4. **"지원 안내" 버튼**: 모집 정보가 비어 모집 섹션이 숨으면 FAQ로 이동한다(빈 앵커로 가지 않게).
5. **헤더 "지원하기"**: 모집 링크(외부)로 바로 가고 새 창임을 스크린리더에 알린다. 링크가 없으면 숨기되 탭이 가운데에 오도록 같은 폭을 비워 둔다.
6. **멤버 그리드**: 좁은 화면에서 한 줄 1장 대신 2장. 카드가 세로로 너무 길어지지 않고 한 화면에 더 많은 얼굴이 보인다.
7. **수상 멤버 칩**: 이름이 정확히 같은 멤버가 한 명일 때만 멤버 카드로 연결(동명이인 오연결 방지). 연결된 칩은 라벤더 글자(`--accent-text`)로 구분.
8. **수상 목록(홈)**: 각 줄이 해당 연도로 필터된 수상 페이지로 이동.
9. **필터**: 선택 결과 수를 스크린리더에 알리고, 결과가 없으면 빈 상태를 보인다. 옵션이 1개 이하면 필터를 숨긴다.
10. **모바일 인트로 안내 문구**: 하단 탭 바에 가리지 않도록 위로 올리고 도시 불빛 위에서도 읽히게 그림자를 줬다.
11. **건너뛰기 링크**: 키보드 사용자를 위한 "본문으로 건너뛰기"를 추가했다.
12. **홈 프로젝트**: 3장 격자 대신 최근 6개를 가로로 넘기는 갤러리로 바꿨다(Apple 하이라이트 갤러리). 첫 카드는 본문 왼쪽 선에, 오른쪽은 화면 끝까지 흘러 더 있다는 걸 보여 준다. 이전·다음 버튼은 넘칠 때만 보인다.
13. **숫자·소개 문단**: 숫자는 큰 글자로 세어 올라가고, 소개 문단은 스크롤에 따라 줄 단위로 밝아진다. 각 구역 제목에 작은 영문 머리글을 달았다.
