# 디자인 참고 자료

사이트의 연출·전환을 정할 때 참고한 자료와, 거기서 가져온 기법·원칙을 남긴다. 화면 구현 위치는 `apps/web/README.md`에 있다.

## 1. Apple MacBook Pro PROLED XDR 디스플레이 페이지

- 주소: https://www.apple.com/kr/macbook-pro/proled-xdr-display/
- 확인 방법: 작업 환경의 네트워크 정책이 apple.com 직접 접속을 막아, 페이지 텍스트 추출본(구역 순서, 이미지 파일 이름, 링크 앵커)으로 구조를 확인했다. CSS·JS 값은 보지 못했으므로 아래 기법은 구조와 Apple 제품 페이지의 공통 연출에서 읽어 낸 것이다. 복제가 아니라 기법만 참고했다.

### 페이지에서 읽은 구조

| 구역                        | 읽은 연출                                                                  |
| --------------------------- | -------------------------------------------------------------------------- |
| 히어로 "꿈의 화면."         | `hero_startframe` → `hero_endframe`: 첫 장면에서 끝 장면으로 넘어가는 영상 |
| "일단 핵심부터." 하이라이트 | 번호 앵커 6개의 가로 갤러리, 이전·다음 버튼, 카드마다 시작·끝 프레임       |
| "찬란함을 당신 손안에."     | 짧은 두 줄 헤드라인 + 큰 이미지, "숫자로 말하는 위대함" 수치 줄            |
| 성능 "M5 Pro. M5 Max."      | 큰 배수 숫자("10.9배")를 반복하는 수치 블록                                |
| 배터리                      | 아주 큰 이미지 위 수치 3개(24시간, 13시간, 30분)                           |
| 프로 워크플로·오디오/카메라 | 알약 탭으로 내용 전환                                                      |

## 2. Apple Human Interface Guidelines — Motion

- 주소: https://developer.apple.com/design/human-interface-guidelines/motion
- 함께 본 것: SwiftUI `Animation.spring(duration:bounce:)`와 `.smooth`, `.snappy`, `.bouncy` 프리셋, "Accessibility → Reduce Motion".

### 원칙과 적용

| HIG 원칙                                           | 사이트에서                                                                                                     |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 움직임에는 목적이 있어야 한다(꾸밈 금지)           | 움직이는 곳은 등장, 누름, 상태 전환, 위치 변화뿐. 호버는 색만 바꾼다                                           |
| 짧고 정확하게                                      | 누름 0.12초, 색 전환 0.25초, 선택 표시 0.45초, 등장 1초 이내                                                   |
| 현실적인 물리(스프링)                              | 이징은 베지어 대신 SwiftUI 스프링을 그대로 계산해 쓴다(아래 표)                                                |
| 즉각적인 피드백                                    | 버튼·탭은 누르는 순간 0.97배(탭 바 0.94배)로 줄고, 떼면 snappy 스프링으로 돌아온다                             |
| 공간 연속성(어디서 와서 어디로 가는지)             | 필터를 바꾸면 남는 카드는 새 자리로 미끄러지고, 페이지를 옮겨도 헤더·탭 바는 제자리에 있고 본문만 크로스페이드 |
| 제스처를 따르는 움직임은 손가락에 붙어 있어야 한다 | 스크롤에 묶인 인트로는 스프링을 쓰지 않고 진행률을 그대로 따른다. 손을 뗄 때 자리 잡는 "LUNA" 한 순간만 바운스 |
| 중단할 수 있어야 한다                              | 모든 전환은 CSS transition·View Transition이라 도중에 다른 입력이 오면 그 자리에서 방향을 바꾼다               |
| 동작 줄이기 존중                                   | 이동·확대·바운스를 모두 빼고 크로스페이드(디졸브)만 남긴다. 인트로는 정적 최종 화면, 숫자는 세지 않고 최종값   |

### 스프링 값

SwiftUI 스프링(response = 한 번 진동하는 시간, bounce = 0이면 넘침 없음)을 감쇠 진동 식으로 계산해 CSS `linear()` 32구간으로 샘플링했다. 지속시간은 스프링이 오차 0.2% 안으로 멈추는 시간이다. 생성은 `apps/web/src/lib/motion.ts`의 `springEase()`와 같은 식이다.

| 토큰              | response | bounce | 멈추는 시간 | 쓰는 곳                                          |
| ----------------- | -------- | ------ | ----------- | ------------------------------------------------ |
| `--spring-smooth` | 0.5초    | 0      | 0.67초      | 등장(1초로 늘려 씀), 페이지·필터 전환, FAQ 펼침  |
| `--spring-snappy` | 0.35초   | 0.15   | 0.45초      | 누름에서 돌아옴, 세그먼트 선택 표시, 화살표 회전 |
| `--spring-bouncy` | 0.5초    | 0.3    | 0.73초      | 강조 한 번(인트로 "LUNA"는 bounce 0.25)          |

## 3. 스크롤 속도

평균적인 스크롤 입력을 기준으로 인트로 길이를 정했다. 값과 계산은 `apps/web/README.md` "스크롤 속도"에 있다.

- 마우스 휠 한 칸 ≈ 100px(Chrome·Edge·Safari 기본 `deltaY`), 이어서 굴릴 때 초당 6~10칸
- 트랙패드 한 번 쓸기 ≈ 400~1,500px(관성 포함)
- 휴대폰 끌기는 손가락과 1:1(한 번 ≈ 화면 0.6장), 튕기기는 화면 1~3장
- 목표: 인트로 전체 3~4초, 단계마다 휠 3칸 이상. 휴대폰에서 세게 튕겨도 로고 장면을 놓치지 않도록 그 지점에 proximity 스냅 하나
